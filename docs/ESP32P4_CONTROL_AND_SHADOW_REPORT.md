# ESP32-P4 阴影检测与三轴 PWM 控制系统报告

## 1. 项目目标

本项目面向纸面书写/绘制场景，目标是在 ESP32-P4 端实时识别纸面阴影，并通过三轴 PWM 电机控制模块调整外部结构，使靠近镜头方向的阴影尽量减小。系统不追求一次性消除所有阴影，而是采用实时判断、持续反馈和小步调整的闭环策略，在保证手/笔和纸面识别稳定的前提下优先降低影响判断逻辑的近端阴影。

当前系统由两部分组成：

1. 阴影检测系统：从摄像头帧中提取纸面、阴影、手/笔等信息，输出可用于控制的特征量。
2. 控制系统：将图像坐标转换为纸面笛卡尔坐标，再通过实时消影逻辑和 PID/PWM 控制三轴电机。

## 2. 总体架构

```mermaid
flowchart LR
    A["MIPI 摄像头"] --> B["RGB565 图像帧"]
    B --> C["灰度化与 96x96 下采样"]
    C --> D["局部亮度归一化"]
    D --> E["ESP32-P4 TFLite Micro 蒸馏模型"]
    E --> F["shadow / exclude / paper 三头输出"]
    F --> G["48x48 掩膜与纸面特征"]
    G --> H["实时消影判断逻辑"]
    H --> I["图像坐标到笛卡尔坐标"]
    I --> J["三轴 PID 控制"]
    J --> K["LEDC 三路 PWM 输出"]

```

系统运行在 `esp32p4_shadow_overlay` 工程中，主循环在显示摄像头画面的同时调用阴影检测，并在自动 PWM 模式开启时调用三轴控制更新。

## 3. 阴影检测系统

### 3.1 输入与预处理

检测模块接收 ESP32-P4 摄像头输出的 RGB565 图像帧。为了适配嵌入式端算力与内存限制，图像首先被转换为灰度图，并下采样到 `96x96`。随后使用积分图实现局部均值归一化，减小整体光照变化对阴影判断的影响。

核心预处理流程如下：

1. RGB565 转亮度灰度。
2. 将原始帧下采样为 `96x96`。
3. 使用局部窗口归一化，让阴影特征更多体现为局部亮度变化，而不是全局曝光差异。
4. 按 TFLite int8 输入量化参数写入模型输入张量。

### 3.2 蒸馏模型设计

当前 ESP32-P4 部署的是 P4 可用的三头蒸馏/学生模型：

- 文件：`outputs/student_open_shadow_v2_seed_p4_b8_int8.tflite`
- 嵌入文件：`esp32p4_shadow_overlay/main/paper_shadow_p4_model_data.cc`
- 输入：`[1, 96, 96, 1]` int8
- 输出：三个 `48x48` int8 logits 图
- 模型大小：`19368` bytes

三个输出头的语义为：

| 输出头 | 作用 | 当前输出索引 |
| --- | --- | --- |
| `exclude_logits` | 手、笔、深色干扰物等需要排除的区域 | `0` |
| `shadow_logits` | 阴影区域 | `1` |
| `paper_logits` | 纸面区域门控 | `2` |

模型采用全 int8 推理，适合 TFLite Micro 在 ESP32-P4 上运行。当前部署模型的优势是体积小、输出结构清晰、可直接服务控制逻辑；限制是该 seed 蒸馏模型仍属于可运行版本，识别质量还需要进一步通过真实标注视频和更完整数据集提升。

### 3.3 掩膜判断逻辑

模型输出不是直接作为最终阴影，而是经过三条件过滤：

```text
final_shadow = shadow >= 0.70
             && exclude < 0.40
             && paper >= 0.20
```

这样可以把用户定义的三类关键元素对应到运行时逻辑：

- 阴影：保留为需要处理的目标。
- 手/笔：进入 `exclude`，避免被误认为阴影。
- 纸：进入 `paper`，让控制系统只关心纸面上的阴影。
- 其余背景：不满足纸面门控，默认不参与控制。

检测模块最终输出的不是单纯图像，而是一组控制可用的特征：

| 特征 | 含义 |
| --- | --- |
| `paper_pixels` | 纸面像素数量 |
| `shadow_on_paper_pixels` | 纸面上的阴影像素数量 |
| `near_shadow_on_paper_pixels` | 靠近镜头方向的阴影像素数量 |
| `hand_pen_on_paper_pixels` | 手/笔遮挡像素数量 |
| `paper_centroid_px` | 纸面中心 |
| `shadow_centroid_px` | 阴影中心 |
| `near_shadow_centroid_px` | 近端阴影中心 |

这些特征由 `shadow_ai_get_last_features()` 提供给控制系统。

## 4. 控制系统

### 4.1 控制目标

控制系统的核心目标不是机械地追踪阴影中心，而是优先减少靠近镜头方向的阴影。因为近端阴影更容易覆盖书写区域，也更容易影响后续判断逻辑。控制逻辑采用如下优先级：

1. 如果纸面不可靠，停止控制。
2. 如果手/笔遮挡比例过高，停止控制，避免把用户手部运动当作环境阴影处理。
3. 如果近端阴影已经低于目标阈值，维持当前状态。
4. 如果近端阴影仍明显，计算新的三轴目标位置。
5. 如果连续多帧没有改善，进入搜索模式，小步切换搜索方向。

### 4.2 图像坐标到笛卡尔坐标

检测系统输出的是 `48x48` 掩膜坐标，例如 `(u, v)`。控制系统需要把它转换到纸面坐标系中的 `(x, y, z)`，因此引入了单应矩阵：

```text
denom = h6*u + h7*v + h8
x = (h0*u + h1*v + h2) / denom
y = (h3*u + h4*v + h5) / denom
z = z_mm
```

当前固件中的默认标定是演示映射：

```text
x = 4*u - 94
y = 4*v - 94
z = 0
```

这意味着 `48x48` 掩膜中心大约映射到纸面原点，`+Y` 方向被定义为靠近镜头的一侧。实际装机时，需要用真实纸面四点重新标定单应矩阵，否则控制方向可能只是近似可用。

### 4.3 实时消影判断

消影判断模块根据每帧特征计算比例量：

```text
shadow_ratio = shadow_on_paper_pixels / paper_pixels
near_shadow_ratio = near_shadow_on_paper_pixels / paper_pixels
hand_pen_ratio = hand_pen_on_paper_pixels / paper_pixels
```

其中近端阴影被加权处理：

```text
priority_shadow_ratio = shadow_ratio + near_shadow_weight * near_shadow_ratio
```

当前默认逻辑中 `near_shadow_weight = 2.0`，表示靠近镜头方向的阴影比普通阴影更重要。控制目标不是立刻让所有阴影为零，而是先让近端阴影低于 `target_near_shadow_ratio`。

当系统判断需要调整时，会根据纸面中心和阴影中心的相对位置生成目标偏移：

```text
dx = paper_center_x - shadow_center_x
dy = paper_center_y - shadow_center_y
```

若近端阴影更严重，则使用更大的近端增益，并沿 `near_camera_dir` 方向增加推离量。Z 轴也会随阴影比例增加抬升量，用于从空间上减少投影。

### 4.4 三轴 PID 与 PWM 输出

三轴控制器把目标笛卡尔点与当前测量点比较，分别计算 X、Y、Z 三轴误差：

```text
error_axis = target_axis - measured_axis
```

每个轴使用独立 PID：

```text
output = kp*error + ki*integral + kd*derivative
```

默认参数：

| 参数 | 默认值 |
| --- | --- |
| `kp` | `0.45` |
| `ki` | `0.02` |
| `kd` | `0.06` |
| `deadband_mm` | `1.5` |
| `integral_limit` | `80.0` |
| `output_limit` | `12.0` |

PID 输出先转换为舵机角度增量，再映射为 PWM 脉宽：

```text
pulse_us = min_pulse_us + t * (max_pulse_us - min_pulse_us)
```

ESP32-P4 端使用 LEDC 输出三路 PWM：

- PWM 频率：`50 Hz`
- PWM 分辨率：`14 bit`
- 舵机脉宽范围：`500 us` 到 `2500 us`
- 当前自动模式中三轴角度限制：`60°` 到 `120°`
- 每次最大步进：`1°`

这些限制可以降低机械结构突然大幅运动的风险。

## 5. 自动控制模式

当前固件默认启用自动 PWM：

```text
CONFIG_SHADOW_SERVO_AUTO_ENABLE=y
CONFIG_SHADOW_SERVO_KEYBOARD_ENABLE=n
```

自动模式启动流程：

1. 初始化阴影检测模型。
2. 初始化三轴控制器和纸面坐标标定。
3. 初始化 LEDC 三路 PWM。
4. 每帧检测阴影特征。
5. 根据实时判断决定是否更新 PWM。
6. 若需要调整，写入新的三路舵机 PWM。

如果键盘手动舵机控制被开启，自动模式会主动禁用，避免两个控制源同时输出。

## 7. 主要风险与限制

1. 当前部署的蒸馏模型是可运行版本，不代表最终高精度版本。其优势是 ESP32-P4 可部署、三输出结构完整；后续仍需要使用手动标注视频继续训练。
2. 纸面坐标变换目前使用示例标定，实际安装后必须重新采集纸面角点并更新单应矩阵。
3. 近端阴影方向目前假设为 `+Y`，如果摄像头安装方向变化，需要同步修改 `near_camera_dir_x_mm` 和 `near_camera_dir_y_mm`。
4. 三轴控制参数是保守默认值，实际电机、连杆和灯光结构不同，需要现场调 `kp/ki/kd`、步进角和角度范围。
5. 系统依赖纸面检测可靠性。当手/笔遮挡过多时，控制会进入 blocked 状态，这是为了避免误动作。

## 8. 后续优化建议

1. 对用户提供的视频进行手动标注，明确标出阴影、手/笔、纸、背景四类区域。
2. 用标注视频做过拟合训练，先让模型在目标场景中稳定识别，再考虑泛化。
3. 重新导出 ESP32-P4 int8 TFLite，并复测三输出顺序和阈值。
4. 实机标定纸面四角，替换当前示例单应矩阵。
5. 在串口日志中记录 `shadow_ratio`、`near_shadow_ratio`、`PWM pulse_us` 和模式状态，用真实数据调控制参数。
6. 对三轴机构增加机械限位和上电归中流程，确保自动控制长期运行稳定。

## 9. 总结

本系统已经形成完整闭环：ESP32-P4 从摄像头获取画面，使用轻量蒸馏模型分离纸面、阴影和手/笔，再把图像特征转换为纸面笛卡尔坐标，通过实时判断逻辑生成目标位置，最终由三轴 PID 控制器输出 PWM 驱动电机。当前版本的重点是跑通嵌入式部署和控制链路，为后续基于真实视频标注的模型提升和实机调参打基础。

整体消除阴影在实际光照与机械限制下并不现实，因此当前策略是更工程化的目标：实时检测、避免误判、优先压低靠近镜头方向的阴影，使纸面判断逻辑更稳定。
